Another little update to [Wasat](https://wasat.davep.dev), this time bumping
the version to [v1.11.0](https://wasat.davep.dev/changelog/#v1110).

After [this morning's change](/2026/10/26/wasat-v1-10-0.html), I made a
start on the work I wanted to do on [Rogallo](https://rogallo.davep.dev/)
and quickly realised that most of what I had planned was better done in
Wasat itself. The short version is: rather than maintaining a
just-this-session ignore list in the application, it made more sense to
handle this in Wasat.

So this release adds an
[`ignore_security_error`](https://wasat.davep.dev/library/client/#wasat.client.Client.ignore_security_error)
method to the client that lets you -- for the current session -- ignore a
particular type of error for a given host/port pair. This makes for a lot
less work needing to be done by the application making use of Wasat. Now
it's just a case of[^1]:

```python
from wasat import Client, IgnorableSecurityError

client = Client()
uri = "gemini://expired.example.com/"

try:
    response = await client.request(uri)
except IgnorableSecurityError as error:
    client.ignore_security_error(uri, error)
    response = await client.request(uri)
```

Obviously, [the code in Rogallo is a bit more involved than the
above](https://github.com/davep/rogallo/pull/499/changes#diff-2cc6b7631653fa64ed1395847b26a1075692c620ee8f4c23b7b96dcc8b365a0d),
but that's the gist of it: try the request, if it fails with an error that
can be ignored, ignore it and try again.

[^1]: Yes, I know the `await` isn't going to work in this example; consider it pseudo-code.
