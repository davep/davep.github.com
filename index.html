Rogallo v3.1.0

2026-10-05 10:13:48 UTC+01:00
2 min read; 10 GFI
Coding

Rogallo v3.1.0 is now available. This release is in response to a recent user request.

Right from the start of the development of Rogallo, I ensured that any MIME types that the application couldn't handle were correctly handed off to the operating system, to allow it to work out what to do. While it is possible for me to do some work to allow images inline -- something I might explore at some point in the future -- Rogallo doesn't currently support this and, accordingly, when faced with image/jpeg or image/png, etc, it delegates to the wider environment.

The problem, of course, is that the user might not have a tool in their environment that's capable of taking over the duties of downloading an image from a gemini URI and displaying it. So the next best thing is that Rogallo itself offers to download the file for you. With v3.1.0 this is now an option.

If you encounter a MIME type that hasn't already been marked for always opening in an external tool, there's a new Download button.

If selected, you'll be asked for a location to save the file.

To augment this, I've also added downloading support for links in the viewer. It might be, for example, that you've already marked image/jpeg and image/png as MIME types that should always be handed off to the operating system (perhaps you have a GUI-based client such as Lagrange or Major Tom installed and it's configured to pick up the URI and handle it). In that case, you'd never be shown the dialog that would allow for downloading. So now, on the occasion that you do want to download within Rogallo, you can navigate to the link and press d. The download dialog will then appear, and you can save the content of the link that way.

ℹ️ Note

If you want to change the binding for the link-based download, you can use the recently added UI element binding facility to bind gemtext_link.download_link to something else.

For now, at least, the download process is pretty simple. It follows the same approach as acquiring the content of a URI for display purposes, but instead writes it to the file you picked. There's no "download manager" or similar and no sticky "download directory". These are things I might consider adding in the future.

Rogallo v3.0.0

2026-10-02 08:45:01 UTC+01:00
3 min read; 10 GFI
Coding

It's been a while since I last published an update to Rogallo. In part this is because I've had other distractions, but also in part because I've not had a huge need to add any new features of late. For the most part I feel Rogallo is "done"1.

I haven't, however, been doing nothing with the code. On and off, over the last handful of weeks, I've been addressing something that I've wanted to tidy up since the early days of development: application configuration. The majority of my Textual-based applications use a simple JSON configuration file, and that's generally good enough. When I started Rogallo I used the same approach. Rogallo has since grown quite a lot and there's much that can be configured and so the "honking great pile-o-JSON" approach was starting to feel quite untidy.

So Rogallo v3.0.0 addresses this. The headline change is that the single JSON file has been replaced with a number of focused YAML files, and some items that were in the original configuration file have been moved out to either the data directory or the state directory, depending on their purpose.

Now for some details on the changes.

❗ Important

There are a lot of changes to how Rogallo is configured. As is mentioned at the end of this post, Rogallo will make a best effort to migrate your old configuration to the new format. However, as a precaution, you might want to think about making a backup copy of your configuration.json file before upgrading Rogallo.

Focused configuration files¶

As mentioned above, whereas before Rogallo kept all of its configuration in a single file, it now looks to a number of different YAML files that focus on a different aspect of configuration. These include:

  • aliases.yaml - Aliases for the Rogallo command line
  • bindings.yaml - Main command and UI element keyboard binding configuration
  • gopher.yaml - Gopher protocol configuration
  • icons.yaml - Configuration of icons used throughout the application
  • preformatted.yaml - Configuration for how preformatted text is handled
  • toolbar.yaml - Configuration for the Rogallo toolbar

General configuration¶

For the configuration items that remain, that aren't exactly focused on a particular Rogallo feature, the settings have moved to general.yaml.

Removal of some application commands¶

Rogallo's design is based around the idea of some "actions" being application-wide commands, and some actions being UI-control-specific. As I worked through the configuration changes I decided that it was time to "demote" some application-wide commands to either being UI-control-specific bindings or just simple configuration properties. With this in mind I've removed the following commands:

  • ChangeCommandLineLocation
  • StripeLinks
  • ToggleANSIEscapeSequenceHandling
  • ToggleCosyLinkNumbers
  • ToggleEmojiRemoval
  • ToggleLinkNumbers

All but ChangeCommandLineLocation are now keyboard shortcuts specific to the viewer widget itself (press F1 when the viewer has focus to get more details). ChangeCommandLineLocation is now a simple configuration property in general.yaml.

UI element action keyboard bindings¶

From the very start, Rogallo has supported some degree of control over keyboard bindings. As mentioned above, there's a split between "application-wide commands" and "UI-element-specific" actions. Until now it's always been possible to configure the bindings for the former, but never the latter.

In other words: you could always configure the binding for the HandOffToOperatingSystem application command (hands the URI of the currently-viewed document to your OS), but you couldn't change the in-viewer binding for the o key, which opens the URI of the focused link in the OS.

Rogallo v3.0.0 adds support for changing the bindings of the latter. So if you wanted to change o to b for opening a URI externally:

gemtext_link.open_link_externally: b

You can find the bindable IDs for each of the UI controls at the bottom of each page for each of the controls.

New Gophermap badges¶

Not directly a configuration setup change, but something I noticed while doing the work, was the fact that Rogallo (and the underlying Gophermap library) didn't handle PNG and RTF item types. They're now directly supported.

Conclusion¶

I believe all of the above changes make it easier to configure Rogallo, and more importantly easier to backup and share the configuration. Technically all of this is one huge breaking change -- everything that was in configuration.json now lives elsewhere. However, I've added some code to Rogallo that detects when you still have a pre-v3.0.0 configuration active, loads up the values, creates the new files, and then renames the old file to configuration.migrated.json. As mentioned near the start of this post, you might want to think about making a backup copy of configuration.json before upgrading.

  1. One last big thing I do want to add is support for tabs. Still to come. ↩

Virtual Fighter Maneuvers

2026-10-01 16:32:09 UTC+01:00
2 min read; 9 GFI
Gaming

I realise I've been a bit quiet on the blog front for a few days, in part because I've also been a bit quiet on the coding front too. Looking at my GitHub contribution graph, the previous three days where I didn't commit anything are the longest run of no-commit days I've had in about 10 months. There are a couple of reasons for this: the first is that I've reached a bit of a natural pause point with my work on Rogallo (there's a biggish update brewing, but I've been taking my time with it), the second is -- as I expected -- getting my hands on the Steam Frame.

I haven't been playing with it exclusively -- when I have a good amount of free time I am back to streaming -- but I have been dipping in on occasion, and some of those occasions would be moments where I'd reach for the MacBook and bang out some code.

I'm still not set up for full-on PCVR, but I have "discovered" a game that runs really well on the Steam Frame, and it's one that's related to a favourite of mine in VR: Virtual Fighter Maneuvers.

Simply put: it's a very cut-down version of VTOL VR, designed to run well on standalone headsets. Graphically it's simplistic, and from a gameplay point of view it's very focused. There's no single-player campaign. There's no multiplayer campaign. There's no story at all. You strap on your headset, fire up the game, jump into a lobby and off you go: dogfight time!

I love it for that. I've always loved flight sims, and they're even more fun in VR. I like the slow pace and the sense of immersion. But if you're going to fly in VR it takes a bit of time to get set up and plan things. This is the total opposite. I love that I can dive in for 30 minutes, have a fun experience, and then be done. It's ideal for quick, casual sessions.

That's not to say I only want to play for those short bursts -- I have played longer sessions -- it's more to point out that it's a game that combines perfectly with the low-activation-energy accessibility of the Steam Frame. It's a game that makes the Frame feel as easy to pick up as the Steam Deck.

Of course, being a mainly multiplayer game, your chances of having a good time are mixed1. I've been into a couple of lobbies that have been really fun, with a good mix of folk, who all seem to have joined to have a good time. I've also joined matches where it's just kids wanting to be edgelords on the Internet. Thankfully, so far, it's more the former than the latter. Sadly, though, there don't seem to be that many people playing it. In my (UK timezone) evenings there's normally, at most, four matches on the go that you might be able to join.

There also seems to be a 1v1 matchmaking service so you can get a ranking by battling folk at a similar level to you (I'm a newb to the game, of course); I've yet to actually get such a match going.

This one is a keeper and I can see myself diving into it often for a good while to come.

  1. It does have bot matches too, so you can do some limited single-player gameplay. ↩

Initial Steam Frame impressions

2026-09-26 11:36:53 UTC+01:00
9 min read; 10 GFI
Gaming

Yesterday evening I finally had the chance to unbox my Steam Frame and have an initial play with it. Here are my impressions of it after playing for a couple of hours. Note that this isn't intended to be any kind of review, just some jotted notes about things I noticed and concluded. The order might appear a little random too.

Unboxing¶

The first thing I noticed was the obvious lack of any actual instructions. Either I missed the obvious, or there was no leaflet and nothing on the box to tell me how to get it up and running. I had already read online what to do so didn't have any issues, but this still strikes me as odd. I guess the Frame isn't intended for the full consumer market and so the kind of enthusiast who plays with SteamVR is likely curious enough to go find information or work things out, but it still feels like an odd omission.

The other thing that feels like a serious omission is the complete lack of any sort of welcome experience. I remember when I first got my Quest 2, the introduction app was a whole thing and did a great job of showing off the hardware. Heck, even the Steam Deck has Aperture Desk Job. It seems like a very odd choice that something new for the Frame wasn't created.

For example, The Lab is a decade old now; it seems strange to me that they didn't refresh it and promote it as a standalone initial experience for the Frame -- perhaps using it to show off some of the new capabilities or something.

Comfort¶

While I did buy the ergonomic kit, I didn't set any of that up right away. I was keen to try the device out so my initial test was without the top strap in place. While I've since fitted it, and find it a useful addition, I'm amazed at just how comfortable the headset is to wear. I've spent many hundreds of hours wearing the Quest 2 and the PSVR2, neither of which was horrible, but both of them felt uncomfortable after some use. Based on my initial impressions the Frame feels like something that could be worn for pretty long sessions without any problem.

To be clear: The Steam Frame is by far the most comfortable headset I've worn. This in turn makes it feel like the headset with the least activation energy required when it comes to being motivated to "jump into VR".

Controllers¶

The controllers are... okay, I guess. Compared to the headset they feel cheap, which they might well be. Based on my experience with the Quest 2, the controllers are the things that take the most punishment and so they're most likely to be the things that need replacing most often. Perhaps they're designed with the right balance of "last long enough" and "affordable to replace".

The main issue I have with the controllers is they seem to have crammed too much into them. They've put all four buttons on the right controller, and a D-pad on the left controller. Perhaps I'm missing something here but this feels like overkill. I found that this made the controllers feel far too busy. All of this also means that the two top buttons (the ones normally used to pull up menus of some description) feel just out of reach. During my time playing last night I found I was having to constantly readjust my grip to reach different buttons, which then meant I was often having to peek under the headset to actually see where my fingers were landing.

Honestly, in terms of ergonomics, I'd say the Frame's controllers are worse than those of the Quest 2, but slightly better than the ones that come with the PSVR21.

There's also the complication of the controller straps that come in the ergonomic kit. I love these sorts of straps (the kind that goes around the back of your hand) as they generally make controller use more comfortable. It's great to not have to keep gripping the controller all the time, and it also feels more natural if you need to throw something in VR. But it really feels like whoever designed the controller layout never spoke with whoever designed the straps. The combination ends up being pretty awkward.

I've never used the Index controllers, but everyone I've spoken to who has always seems to sing their praises. Based on that, the Frame's controllers feel like they can't have come from the same company.

Inside the headset¶

I've read a good few comments from people on Reddit that say that the display in the headset is pretty dark. That wasn't my experience at all. Out of the box I found the display bright enough, and that wasn't even turned up as high as it will go.

The other thing I found was that the display felt like the clearest one I've tried out yet. I wear glasses; I'm short-sighted and have an astigmatism that needs correcting. Given the design of the headset there's no way I was going to wear my specs while using it, so for the moment I'm playing unaided2. Despite that I found the display very readable (to be fair, I'm not that short-sighted).

What is slightly disappointing is the lack of an actual "home" when you boot up the headset. This feels like a missed opportunity. Like, sure, the floating menus and the stark landscape are fine and do the job, but the actual home to exist in always felt like a fun thing. Even the Quest 2 has this -- surely it could be done on the Frame?

Audio¶

I really like the audio. My VR audio experience comes from the stock Quest 2 and also stock PSVR2. The Frame is obviously very similar to the Quest 2, in that the speakers are "near" your ears but don't cover them in any way. I like this. I like this a lot. I find this a really comfortable way to experience VR (and, while it's not an issue at the moment, the ideal setup for recording your voice for video-making or streaming purposes -- you're less likely to end up shouting). I've never liked the PSVR2 in-ear buds so I'm glad it's nothing like that.

While playing, I found that the sense of direction of sounds was pretty spot on, which is something that very obviously matters to immersion. That level of immersion, combined with an awareness of your own surroundings, feels like just the right balance.

Battery life¶

The battery life is not great, it has to be said. I think I got something like 40 minutes out of the device when I first booted it up. In all fairness, I can't remember what level it was on to start with, and I was also doing an OS upgrade, controller update, and the installation of a game or two.

The second part of my initial session started with something like 95% battery available. That second session ended up on about 20% battery left after playing Alyx for the better part of an hour, give or take (I didn't make a point of actually timing it).

I feel like, with a full charge, and depending on what I do, I might get around 90 minutes out of the device. This feels less than I'd get out of the Quest 2 back in the day.

All of this was, of course, playing a game locally on the headset itself. It will be interesting to see how it compares when in PC-based PCVR streaming mode using the supplied dongle.

Given my interest in using this mostly in standalone mode, I can see myself buying an external power unit and hooking it up while it's stuck in a pocket or something.

Ergonomic kit¶

The ergonomic kit feels like a thing that should have been included in the price, if I'm honest. The additional strap for the headset is, as I mentioned above, nice to have and improves the comfort from comfortable to very comfortable. The straps for the controllers feel a little cheap but do the job.

I've not tried out the nose guard thing yet. There's no doubt that a lot of light leaks around the nose, but at the same time that's actually quite handy for quickly glancing at the world around you if you need to be able to check on something (your phone, or where your fingers are on the controller because of the issues I mention above).

Now, this might just be me being a bit dense: I found the instructions that came with the kit kind of confusing when it came to the controller straps. I got there in the end, but I feel like the visuals printed on the box could have been so much better.

Thankfully my kit was complete. I've seen reports of people finding broken parts, missing parts, or things like two right-handed controller straps rather than a left and a right.

Gaming¶

For my initial session I only played games standalone. While I do have a PC for PCVR purposes, it's still packed away after my move last year. I will drag it out and give it a go at some point, but the standalone gaming abilities are what interest me most at the moment.

Gunman Contracts - Stand Alone¶

The first game I decided to try out was Gunman Contracts - Stand Alone. While the "Stand Alone" in the name is in reference to it no longer being a mod for Half-Life: Alyx, my understanding is that it is intended to be playable standalone on the Steam Frame.

It isn't. It so very isn't.

The FPS was horrible, and I noticed lots of graphical distortion as I tried to play. I never made it out of the home bunker as the whole thing was just a laggy mess.

This doesn't surprise me though. Based on other reviews it looks like it's not the best experience even when playing in full PCVR mode. I've also played it flat-screen on the Steam Deck and it's okay there, but obviously needs some work.

I will revisit this, as I noticed in the settings for it that everything seemed to be turned up to the max. Textures were on Ultra for example, which seems like a wild choice out of the box for a game running on a standalone VR headset. Given this I'm going to assume the game makes zero effort to detect the environment it's running in and to configure good defaults.

Gun Club VR¶

Next up I tried Gun Club VR. This is a game I've played before native to the Quest 2, and also in PCVR. Given it's an older game I had high hopes for it. I was right to. This was pin-sharp and buttery smooth. In terms of how it looked and felt in the headset it was night and day compared to Gunman Contracts.

Sure, I'm comparing apples and oranges there in terms of game age and what's being asked of the hardware, but I think it's a good comparison of the different ends of that spectrum.

While Gunman Contracts left me concerned that a lot of VR gaming would be off-limits on the Frame, Gun Club VR gave me hope that many of the classics will run well (perhaps after some tweaks by the authors).

Half-Life: Alyx¶

The third and final game I tried out was Half-Life: Alyx. I've played this in full PCVR mode before, and do feel it's pretty much the peak VR experience. The idea that this could work standalone was wild to me. I know Valve have worked hard on making it work, and are promoting it to the point of bundling it with the Frame3, but it still felt like it was going to be a bad time.

It wasn't a bad time. It was a good time.

While it's very obvious that the graphics have been dialled down, and while I did see a fair bit of pop-in of assets from time to time, generally it looked good and performed well. In my peripheral vision I could obviously see that the resolution was super-low, but no matter where I was directly looking, I saw a quality image (presumably eye-tracked foveated rendering at work, although I've not checked if it is used in Alyx). There was almost no stutter, no lag to speak of, and it felt as good as I remember when playing it in full PCVR mode.

Conclusion¶

Overall my first experience is pretty positive. Out of the box the Steam Frame is the most comfortable VR experience I've had yet. Given I'm writing this just one week after getting the purchase invitation email, I have high hopes for this device. It seems obvious that there's a load of software and firmware improvements to come, and I can imagine a good third-party market of add-on products to augment the use of the headset (mics, headphones, care and storage, power without full tether, etc.). I also imagine there will be a scramble to optimise a good number of VR games and experiences to get them working well standalone.

It is, without question, expensive for what it is. I very much doubt that this was Valve's intention or doing. The demand for various types of hardware is having a broad impact and I don't need to detail that. Taking this fact into account, this feels like a great little product that's only going to improve with time.

While I'm not sure I'll return to recording VR videos again, at least not with the frequency I used to, I will be returning to enjoying playing VR again thanks to this little device making it very accessible.

  1. I'd place the PSVR2 higher than the Frame if it wasn't for the fact that I find the grips of the controllers far too bulky and very difficult to keep gripped for an extended period of time. ↩

  2. I will be getting prescription inserts when they become available. ↩

  3. Pity us poor souls who already own it I guess. ↩

Siri is broken

2026-09-24 08:12:05 UTC+01:00
2 min read; 11 GFI
Tech

I think, in part, I regret upgrading any of my Apple devices to the 27 line of operating systems. While my experience as a whole has been pretty favourable, the one thing I was looking forward to is not just disappointing, but is a huge step backwards.

I don't use Siri for many things, but I do use it a lot for a small number of core things. On any given day I'll lift my watch up and speak to it to set a timer or a reminder. Occasionally I'll ask other things, but they're the main uses. Thanks to the fairly recent addition of on-device voice handling, these requests have been near-instant.

With the new Siri that comes with iOS 27, etc., if I'm really lucky the reply will be super slow (getting on for 20 seconds or so to do the job), but more often than not it just doesn't work at all. Either it tells me that my main device isn't available right now1 (which I take to mean my iPhone, which is wild given it's always in my pocket at the time), or it just busy spins for ages and then simply times out and does nothing.

If I try to use Siri on the iPhone itself, it either just busy waits for ages without getting anything done, or it finally tells me it isn't working.

I was one of the people who upgraded to the 16 Pro because of the promise of "Apple Intelligence". I was, unsurprisingly, kind of annoyed that they didn't deliver. But it was fine, the phone is a good one and it's still serving me well. Also, if I'm honest, I was comfortable with the idea that they chose to not really implement anything2 rather than implement something bad.

Sadly though, based on my experience so far, they've implemented something bad. Since upgrading, on the Watch and iPhone, I've found that it's either horrifically slow or it just doesn't work. On top of that, I've lost all the benefit of the on-device voice handling of my watches.

  2. I mean, of course, they did do the image playground and writing tools, but they're hardly the leap forward in assistant intelligence that was originally being hinted at. ↩
